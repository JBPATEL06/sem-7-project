## 3. Cloudflare Named Tunnel & Domain Prerequisites
- A **Named Tunnel** (`cloudflared tunnel create <NAME>`) requires an owned domain delegated to Cloudflare DNS so that a CNAME record (e.g. `mcp.yourdomain.com`) can be created.
- **Paths Available**:
  - **Path 1 (Custom Owned Domain)**: If you or the team already have a domain in Cloudflare, we will configure the tunnel CNAME to point to it. If not, a domain can be purchased via Cloudflare Registrar (~$8–$10/year).
  - **Path 2 (Zero-Cost Quick Tunnel Fallback)**: For immediate development and zero-cost operation without purchasing a domain, we support Cloudflare **Quick Tunnels** (`cloudflared tunnel --url http://localhost:3000`), generating an instant, free `https://*.trycloudflare.com` URL displayed dynamically in the UI.

## 4. Auth Scope Clarification: Data Tables Only vs Full Supabase Auth
- **Recommendation: DATA TABLES ONLY (Option A)**.
- **Rationale**: Since the core objective is to package AI Manager as a standalone Electron `.exe` running entirely on the user's PC, binding authentication to Supabase Cloud (`auth.users`) would break **offline capability** (users wouldn't be able to log in without internet access).
- **Confirmed Structure**:
  - Keep existing custom bcrypt (10 salt rounds) + JWT Auth & RBAC (`user`/`admin`) with local JSON fallback (`.ai-manager/users.json`).
  - Migrate **DATA TABLES ONLY** (`projects`, `activity_logs`, `settings`) to Supabase PostgreSQL, linking records to `public.users(id)` instead of `auth.users(id)`.
  - If you specifically prefer migrating auth credentials to Supabase GoTrue (`auth.users`), we can execute Option B, but Option A is recommended for desktop resilience.
