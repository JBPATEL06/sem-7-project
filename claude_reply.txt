### 1. AUDIT: Code & Pattern Reuse
After reviewing the Kankali context and the current codebase, here are the patterns we should extract and reuse for Days 2-10:

*   **Rule Engine**: The QA diagnostic rules currently hardcoded in `server/qaRoutes.ts` can absolutely be abstracted into a `server/utils/ruleEngine.ts`. We can define a standard `Rule` interface (`evaluate(context) => Diagnostic[]`). This exact same engine can then be fed a different set of rules for the Testing page (Day 8).
*   **Local JSON Store**: The `fs.readFileSync`/`writeFileSync` pattern used for `projects.json`, `activity.json`, and the local `users.json` fallback is currently duplicated across route files. We should extract a generic `JsonStore<T>` utility (`server/utils/jsonStore.ts`) that handles read/write, error catching, and basic CRUD. This will instantly serve Git issues (Day 2), Excalidraw metadata (Day 3), and Diagrams (Day 6).
*   **Frontend API Fetching**: Every custom hook (`useProjects`, `useQa`, `useAdmin`) manually constructs the `fetch` call, manually attaches the `Authorization: Bearer` token from context, and manually parses JSON/errors. We need a unified `apiClient.ts` or `useApi` hook to eliminate this repetitive boilerplate.

### 2. TOKEN-EFFICIENT ARCHITECTURE
To minimize token burn over the next 9 days, we need to standardize and build an internal toolkit:

*   **Consistent Scaffolding**: Yes, we will stick to the exact triad pattern: `server/[feature]Routes.ts` (backend), `src/hooks/use[Feature].ts` (state management), and `src/pages/[Feature]Page.tsx` (UI).
*   **Shared Toolkit**: Before starting Day 2, we should spend one fast session building the internal toolkit (`JsonStore`, `RuleEngine`, `apiClient`). Future prompts can then just say: *"Build Git Management using JsonStore for issues and the standard triad template,"* bypassing the need to re-explain file system access or token attachment.
*   **Concrete File Convention**:
    *   Backend: `server/routes/`, `server/utils/`, `server/services/` (to keep `index.ts` clean).
    *   Frontend: `src/api/client.ts`, `src/hooks/`, `src/pages/`, `src/components/`.
